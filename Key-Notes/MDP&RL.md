# 马尔可夫决策过程与强化学习

# 1 马尔可夫决策过程 (Markov Decision Processes, MDP)
## 1.1 基础概念
### 1.1.1 序列决策问题 (Sequential Decision Problem)
* **核心概念**：智能体（Agent）的最终效用（Utility）取决于其做出的**一系列决策**。
* **特点**：序列决策问题综合考虑了效用、环境的不确定性（Uncertainty）以及感知（Sensing）。
* **目标**：最优行为需要在不确定的环境中，平衡采取行动的风险与回报。

### 1.1.2 转移模型 (Transition Model)
* **定义**：转移模型通常表示为 $T(s,a,s')$，用于描述在某个状态下执行某个动作后所产生的结果。
* **随机性 (Stochastic)**：状态转移的结果具有随机性。我们用概率 $P(s'|s,a)$ 来表示：在当前状态 $s$ 下，执行动作 $a$ 之后，到达下一个状态 $s'$ 的概率。
* **马尔可夫假设 (Markovian)**：假设状态转移满足“马尔可夫性质”。即从状态 $s$ 转移到 $s'$ 的概率**仅取决于当前状态 $s$**，而与智能体经历的早期历史状态无关。（该性质以俄罗斯数学家安德烈·马尔可夫命名）。

### 1.1.3 马尔可夫决策过程 (MDP)
* **定义**：一个具备完全可观察性（Fully Observable）、处于随机环境中、具有马尔可夫转移模型和加性奖励（Additive Rewards）的序列决策问题，被称为**马尔可夫决策过程（MDP）**。
* **MDP 的组成要素**（通常被定义为一个元组）：
    1. **状态集 (States)**：所有可能状态的集合 $S$ ($s \in S$)
    2. **动作集 (Actions)**：所有可能动作的集合 $A$ ($a \in A$)
    3. **转移函数 (Transition Function)**：$T(s,a,s')$，即动作 $a$ 导致状态从 $s$ 转移到 $s'$ 的概率 $P(s'|s,a)$
    4. **奖励函数 (Reward Function)**：$R(s,a,s')$，在特定状态转移过程中获得的即时奖励
    5. **初始状态 (Start State)**：$s_0$
    6. *（可选）* **终止状态 (Terminal state)**

### 1.1.4 Q-State

“Agent（智能体）已经决定/承诺要执行某个动作，但该动作的最终结果还未在环境中结算。”

- 情境：Agent 已经在大脑里拍板决定：“我要向左走！”（"committed to the action"）。
- 特点：但是，由于环境存在不确定性（正如你上一张课件所讲的，轮子可能会打滑，风可能会把你吹偏），这个“向左走”的动作虽然发出了指令，但最终会走到哪里、拿到多少奖励，环境还没有给出结果（"has not done it yet" 或 outcome not materialized）。
- 本质：这是一种中间状态。它衡量的是“在状态 $s$ 下，执行动作 $a$ 的预期好坏程度”，即动作价值 $Q(s, a)$。

## 1.2 策略 (Policy)
### 1.2.1 策略 (Policy)
* **MDP 的解法要求**：简单的“固定动作序列”无法解决 MDP 问题，因为环境具有随机性，智能体可能根本无法按照预定路线到达目标状态。
* **定义**：MDP 的解决方案必须明确指出，智能体在**任何可能到达的状态下**应该采取什么行动。这种映射状态到动作的规则被称为**策略 (Policy)**，用符号 $\pi$ 表示。
* **表示方法**：$\pi(s)$ 表示根据策略 $\pi$，在状态 $s$ 下推荐采取的具体动作。

### 1.2.2  最优策略 (Optimal Policy)
* **策略的评估**：由于环境的随机性，即使每次都执行完全相同的策略，智能体也可能经历不同的环境历史（路径）。因此，一个策略的质量（好坏）是由该策略产生的所有可能历史路径的**期望效用 (Expected Utility)** 来衡量的。
* **最优策略的定义**：**最优策略 (Optimal Policy)** 记作 $\pi^*$，它是指在所有可能策略中，能够产生**最高期望效用**的那个策略。
* **示例说明**：以经典的“网格世界 (Grid World)”为例，假设每个非终止状态的每步移动代价（奖励）为 $R(s) = -0.04$，智能体会计算出一个最优策略 $\pi^*$，表现为在每个网格上都有一个明确的箭头（如向上、向左），指导智能体以最佳路径走向高分终点并避开陷阱。

## 1.3 状态序列的效用 (Utility of State Sequences)
* **核心问题**：如何计算一连串状态序列的总效用？智能体对不同的奖励序列应该具备什么样的偏好？
* **偏好考量**：
    * **多与少 (More or less)**：通常智能体偏好总和更大的奖励序列，例如 $[2, 3, 4]$ 优于 $[1, 2, 2]$。
    * **早与晚 (Now or later)**：在总奖励相同的情况下，智能体通常偏好尽早获得奖励（落袋为安），例如 $[1, 0, 0]$ 优于 $[0, 0, 1]$。

### 1.3.1 折扣机制 (Discounting)
* **概念动机**：追求奖励总和最大化是合理的，同时“偏好近期的奖励胜过远期的奖励”也是符合逻辑的。
* **解决方案**：引入折扣机制。随着时间的推移，未来获得的奖励的当前价值会呈现**指数衰减 (decay exponentially)**。

### 1.3.2 平稳偏好 (Stationary Preferences)
* **基本假设**：假设智能体对状态序列的偏好是“平稳的 (Stationary)”。
* **定义**：如果两个状态序列都以相同的初始状态 $r$ 开始，那么这两个包含 $r$ 的序列的偏好顺序，必须与去掉首个状态 $r$ 后的序列偏好顺序完全保持一致。
    * **数学表达**：$[r, s_1, s_2, \dots] \succ [r, s'_1, s'_2, \dots] \iff [s_1, s_2, \dots] \succ [s'_1, s'_2, \dots]$
* **平稳性的推论**：平稳性假设具有很强的约束力。数学上可以证明，只有两种连贯的方式来为状态序列分配总效用：
    1. **加性奖励 (Additive rewards)**：各阶段奖励直接相加，不随时间衰减。
       $$U([s_0, s_1, s_2, \dots]) = R(s_0) + R(s_1) + R(s_2) + \dots$$
    2. **折扣奖励 (Discounted rewards)**：引入折扣因子 $\gamma$（通常 $0 \le \gamma < 1$），每延后一步，奖励乘以一个 $\gamma$。
       $$U([s_0, s_1, s_2, \dots]) = R(s_0) + \gamma R(s_1) + \gamma^2 R(s_2) + \dots$$

### 1.3.3 无限效用与收敛性 (Infinity Utilities?)
* **问题背景**：如果环境不存在终止状态，或者智能体永远在环境中运行（如赛车游戏中的智能车一直行驶），总效用会怎样？
* **发散问题**：如果采用无折扣的“加性奖励”，无限序列的总效用将会累加至无穷大 ($\infty$)，导致无法比较不同策略的优劣。
* **折扣机制的收敛作用**：引入折扣因子 $\gamma$ (<1) 后，即使序列是无限长的，其总效用也是**有限的 (finite)**。
    * **数学证明**：假设在任何状态下能获得的最大单步奖励为 $R_{max}$，利用等比数列求和公式，可以计算出无限折扣奖励总和的上限：
      $$U([s_0, s_1, s_2, \dots]) = \sum_{t=0}^{\infty} \gamma^t R(s_t) \le \sum_{t=0}^{\infty} \gamma^t R_{max} = \frac{R_{max}}{1 - \gamma}$$
    * **意义**：这保证了强化学习算法在无限时间范围的任务中，依然能算出收敛的有限数值进行策略优化。

*(注：课件中提到的 Quiz 思考题——如果将序列的效用定义为该序列中获得的最大单次奖励，它满足平稳偏好吗？答案是不满足。因为最大值操作会掩盖序列中其他元素的差异，破坏了上述的等价推导关系。)*

# 2 Value Iteration & Policy Iteration
## 2.1 贝尔曼方程
## 2.1.1 最优量 (Optimal Quantities)
在解决 MDP 问题时，我们需要定义几个关键的“最优量”来评估状态和动作：
* **V\*(s)**：状态 s 的最优价值（Value/Utility）。它表示智能体从状态 s 开始，并且在此后一直采取**最优策略**所能获得的期望效用。
* **Q\*(s, a)**：q-状态 (s, a) 的最优价值。它表示智能体在状态 s 强制采取动作 a，并且在此之后一直采取**最优策略**所能获得的期望效用。
* **π\*(s)**：状态 s 的最优策略（Optimal Policy）。它直接指出在状态 s 下能带来最大效用的**最优具体动作**。

### 2.1.2 贝尔曼方程 (Bellman Equation)
* **核心思想**：如何计算一个状态的价值？贝尔曼方程给出了状态价值的**递归定义**。它非常类似于期望最大化（expectimax）搜索。
* **基本关系式**：
    1. 状态的最优价值等于该状态下能产生最大收益的动作的 Q 值：
       $$V^*(s) = \max_a Q^*(s, a)$$
    2. 动作的 Q 值等于执行该动作后，所有可能转移到的下一个状态的（即时奖励 + 折扣后的下一状态价值）的期望和：
       $$Q^*(s, a) = \sum_{s'} T(s, a, s')[R(s, a, s') + \gamma V^*(s')]$$
* **完整的贝尔曼方程**（将上述两步结合）：
    $$V^*(s) = \max_a \sum_{s'} T(s, a, s')[R(s, a, s') + \gamma V^*(s')]$$

---

## 2.2 价值迭代 (Value Iteration)
### 2.2.1 算法流程
* **算法目的**：贝尔曼方程只是一个等式，而“价值迭代”是一种真正用来**计算**出这些最优价值的算法。
* **计算步骤**：
    1. **初始化**：从 V_0(s) = 0 开始（0 表示如果没有剩余的时间步，期望获取的奖励总和就是 0）。
    2. **迭代更新**：给定第 k 步的价值向量 V_k(s)，执行一轮类似 expectimax 的更新，计算出 k+1 步的价值：
       $$V_{k+1}(s) \leftarrow \max_a \sum_{s'} T(s, a, s')[R(s, a, s') + \gamma V_k(s')]$$
    3. **收敛**：不断重复上述迭代步骤，直到 V(s) 的值不再发生变化（即达到收敛）。
* **复杂度**：每次迭代的时间复杂度为 O(S²A)（其中 S 是状态数量，A 是动作数量）。
* **理论保证 (Theorem)**：数学上可以证明，无论初始值如何，价值迭代算法最终都会**收敛到唯一的最优价值**。

### 2.2.2 贝尔曼方程 vs. 价值迭代 
* **贝尔曼方程**：用于**刻画 / 描述 (characterize)** 最优值。它是一个恒等式（使用 `=` 号），方程左右两边都有未知的 `V*`。
    * `V*(s) = max_a Σ_s' T(s,a,s') * [R(s,a,s') + γ V*(s')]`
* **价值迭代**：是一个用于**计算 (computes)** 这些最优值的具体算法步骤。它是一个赋值操作（使用 `←` 号），用第 `k` 步的旧值计算出第 `k+1` 步的新值。
    * `V_{k+1}(s) ← max_a Σ_s' T(s,a,s') * [R(s,a,s') + γ V_k(s')]`

## 2.3 策略迭代 (Policy Iteration)

### 2.3.1. 策略评估的核心概念 (Policy Evaluation)
* **核心目标**：我们想要评估一个给定的策略 $\pi$ 到底有多好？（即：如果我严格按照策略 $\pi$ 去行动，我的表现会怎样？）
* **搜索树的结构变化（重点图解含义）**：
    * **寻找最优动作时**：状态节点下会有多个动作分支，智能体需要在这其中寻找最优解（带有 `max` 操作）。
    * **遵循固定策略时**：因为策略 $\pi$ 已经规定了在状态 s 下必须执行的动作 $\pi(s)$，所以**选择权消失了**。状态节点下只剩下一条唯一的动作分支。

### 2.3.2 固定策略的效用 (Utilities for a Fixed Policy)
* **概念**：我们计算在固定策略（通常是非最优策略）下，状态 s 的效用。
* **$V^\pi(s)$ 的定义**：表示从状态 s 开始，并且之后一直**遵循策略 $\pi$** 所能获得的期望总折扣奖励（expected total discounted rewards）。
* **固定策略的贝尔曼方程**：
    $$V^\pi(s) = \sum_{s'} T(s, \pi(s), s') [R(s, \pi(s), s') + \gamma V^\pi(s')]$$
    *(注意：与最优价值的贝尔曼方程相比，这里**没有了 $\max_a$ 操作**，因为动作 $a$ 已经被固定为 $\pi(s)$。)*

### 2.3.3 策略评估的计算方法 (Calculating Policy Evaluation)
* **问题**：我们如何具体计算出固定策略 $\pi$ 下的所有 $V$ 值？
* **方法一：迭代更新 (Idea 1: Turn recursive equations into updates)**
    * 类似于价值迭代算法，我们将递归方程转化为不断更新的迭代步骤。
    * **初始化**：$V_0^\pi(s) = 0$
    * **迭代公式**：$V_{k+1}^\pi(s) \leftarrow \sum_{s'} T(s, \pi(s), s') [R(s, \pi(s), s') + \gamma V_k^\pi(s')]$
    * **算法效率 (Efficiency)**：每次迭代的时间复杂度为 **$O(S^2)$**。
    *(深度解析：为什么不是价值迭代的 $O(S^2A)$？因为动作是被策略固定的，不需要遍历 A 个动作去求最大值，所以省去了 A 的计算量，速度更快。)*
* **方法二：求解线性方程组 (Idea 2: Use a linear system solver)**
    * 因为方程中去掉了非线性的 `max` 算子，剩下的贝尔曼方程实际上就是一个**纯线性方程组 (a linear system)**。
    * 包含 S 个未知数（每个状态的 V 值）和 S 个线性方程。因此，可以直接使用标准的线性代数求解器（如矩阵求逆）一步到位算出精确解。

### 2.3.4 策略提取：从 V 值提取 (Policy Extraction from Values)
* **情景假设**：假设我们已经通过某种方法（如价值迭代）算出了所有的最优状态价值 $V^*(s)$。
* **核心问题**：我们该如何行动？（How should we act?）
* **提取方法**：仅仅知道走到哪个状态能拿多少分是不够的，我们必须执行一次**单步向前看的微型期望最大化搜索 (a mini-expectimax, one step)**，才能决定当前该采取什么动作。
* **公式表达**：
    $$\pi^*(s) = \arg\max_a \sum_{s'} T(s, a, s') [R(s, a, s') + \gamma V^*(s')]$$
    *（注：$\arg\max_a$ 的意思是“返回能使后面这串求和公式达到最大值的那个动作 $a$”。）*
* **概念定义**：这个过程被称为**策略提取 (Policy Extraction)**，因为它从价值中推导/提取出了隐含的最优策略。

### 2.3.5 策略提取：从 Q 值提取 (Policy Extraction from Q-Values)
* **情景假设**：假设我们现在拥有的不是 V 值，而是所有的最优 Q 值 $Q^*(s, a)$。（如课件图所示，每个网格被划分成了多个三角形，每个三角形代表在当前格子采取特定方向动作的 Q 值）。
* **提取方法**：超级简单 (Super easy)！
* **公式表达**：
    $$\pi^*(s) = \arg\max_a Q^*(s, a)$$
    *（注：直接在当前状态的所有可用动作中，挑出 Q 值最大的那个动作即可。）*
* **核心结论**：**直接从 Q 值选择动作，比从 V 值选择动作要容易得多。**
    *(深度解析：从 V 提取策略时，你必须知道环境的转移模型 $T$ 和奖励函数 $R$ 才能计算期望；但如果有了 Q 值，你不需要知道环境是如何运作的，直接比大小就能做出决策。这也是后续“Q-Learning”算法的核心动机。)*


### 2.3.6 策略迭代算法 (Policy Iteration)
* **算法定位**：策略迭代是求解最优价值的另一种替代方法（相对于价值迭代）。
* **核心循环（两大步骤）**：
    1. **策略评估 (Policy evaluation)**：计算当前某个固定策略下的效用值。注意，此时计算出的效用值**不是**最优效用，而是该特定策略下的效用。持续迭代直到该策略的价值收敛。
        * **公式**：对于固定的当前策略 $\pi_i$，迭代直至价值收敛：
          $$V_{k+1}^{\pi_i}(s) \leftarrow \sum_{s'} T(s, \pi_i(s), s') [R(s, \pi_i(s), s') + \gamma V_k^{\pi_i}(s')]$$
    2. **策略改进 (Policy improvement)**：利用上一步收敛得到的（非最优的）未来价值，通过“单步向前看 (one-step look-ahead)”来更新并提取出一个更好的新策略。
        * **公式**：利用策略提取进行单步向前看，得到改进后的策略 $\pi_{i+1}$：
          $$\pi_{i+1}(s) = \arg\max_a \sum_{s'} T(s, a, s') [R(s, a, s') + \gamma V^{\pi_i}(s')]$$
* **循环终止**：不断重复上述“评估 -> 改进”的步骤，直到策略不再发生任何改变（即策略收敛）。
* **算法特性**：
    * **依然最优 (Still optimal)**：策略迭代最终收敛得到的结果同样是全局最优解。
    * **效率优势**：在某些特定条件下，策略迭代的收敛速度可能会比价值迭代**快得多 (much faster)**。

## 2.4 对比与总结
### 2.4.1 算法对比：价值迭代 vs. 策略迭代 (Comparison)
* **共同点**：无论是价值迭代还是策略迭代，它们计算的最终目标是完全相同的（即算出所有的最优价值和最优策略），并且它们都属于用于解决 MDP 问题的**动态规划 (Dynamic programs)** 算法。
* **价值迭代 (Value iteration) 的特点**：
    * 每次迭代都会同时更新状态价值，并**隐式地 (implicitly)** 更新策略。
    * 我们在算法运行期间并不显式地追踪策略，但在动作上取 `max` 操作，实际上就是在隐式地重新计算当前的最优策略。
* **策略迭代 (Policy iteration) 的特点**：
    * 我们首先进行多次快速的“传递 (passes)”来更新固定策略下的效用。（这步计算**很快**，因为每个状态只考虑这一个固定的动作，不需要去遍历所有动作求最大值）。
    * 在策略被完全评估之后，才选择一个新的策略。（这一步涉及动作遍历找最大值，计算**较慢**，类似于价值迭代中的一次更新）。
    * 每次改进提取出的新策略，必定比旧策略**更好**（除非已经达到了最优，此时算法结束）。

### 2.4.2 MDP 算法全局总结 (Summary: MDP Algorithms)
* **目标导向速查表 (So you want to....)**：
    * **目标 1**：如果想计算**最优价值 (Compute optimal values)** $\rightarrow$  使用 **价值迭代** 或 **策略迭代**。
    * **目标 2**：如果想计算某个**特定（固定）策略下的价值 (Compute values for a particular policy)** $\rightarrow$  使用 **策略评估**。
    * **目标 3**：如果想把已经算好的**价值转化为具体的行动策略 (Turn your values into a policy)** $\rightarrow$  使用 **策略提取**（即单步向前看）。

* **本质的统一性 (These all look the same!)**：
    * 这些公式看起来几乎一模一样！这并非巧合。
    * 它们本质上是一回事——它们全都是**贝尔曼更新 (Bellman updates)** 的不同变体。
    * 它们全都使用了“单步向前看的期望最大化片段 (one-step lookahead expectimax fragments)”。
    * **唯一的核心区别**就在于：公式里代入的究竟是一个**固定的策略 (fixed policy, 没有 max 操作)**，还是需要在所有可能的动作中去**求最大值 (max over actions)**。

# 3 Reinforcement Learning
## 3.1 基础概念
### 3.1.1 强化学习的基本思想 (Basic Idea)
强化学习描述了**智能体 (Agent)** 与**环境 (Environment)** 之间的交互过程。
* **交互循环**：智能体在环境中采取**动作 (Actions, $a$)**，环境会反馈新的**状态 (State, $s$)** 和**奖励 (Reward, $r$)**。
* **核心特征**：
  * 通过“奖励 (Rewards)”的形式接收环境的反馈。
  * 智能体的效用 (Utility) 完全由奖励函数定义。
  * 目标是（通过学习）采取最佳行动，以**最大化期望累积奖励 (Maximize expected rewards)**。
  * 所有的学习过程都建立在**对结果的观测样本 (Observed samples)** 基础之上（即在试错中学习）。

### 3.1.2 强化学习与马尔可夫决策过程 (RL vs. MDP)
强化学习在底层仍然假设环境是一个**马尔可夫决策过程 (MDP)**：
* **继承自 MDP 的概念**：
  * 状态集合 $S$ ($s \in S$)
  * 动作集合 $A$ (每个状态下可执行的动作)
  * 转移模型 $T(s,a,s')$ (在状态 $s$ 采取动作 $a$ 转移到状态 $s'$ 的概率)
  * 奖励函数 $R(s,a,s')$
  * 目标依然是寻找一个最优的**策略 $\pi(s)$ (Policy)**。

* **强化学习面临的新挑战 (What's New)**：
  * **未知环境**：我们**不知道**转移模型 $T$ 和奖励函数 $R$（即不知道动作会产生什么具体后果，也不知道具体会得到多少奖励）。
  * **必须探索**：智能体必须亲自去尝试不同的动作，经历不同的状态，才能收集数据并进行学习。


### 3.1.3 基于模型的学习 (Model-Based Learning)
**核心思想**：先利用经验（数据）学习建立一个环境的近似模型，然后假定这个学到的模型是完全正确的，并基于它来求解价值或策略。

**两步走框架**：
* **Step 1: 学习经验 MDP 模型 (Learn empirical MDP model)**
  * **估计转移模型 $\hat{T}(s, a, s')$**：统计在状态 $s$ 执行动作 $a$ 后转移到状态 $s'$ 的次数，然后进行归一化 (Normalize) 处理，得到经验转移概率。
  * **发现奖励函数 $\hat{R}(s, a, s')$**：在经历具体的 $(s, a, s')$ 转移时，直接记录观察到的经验奖励值。
* **Step 2: 求解学到的 MDP (Solve the learned MDP)**
  * 利用经典的 MDP 求解算法（如：策略迭代 Policy Iteration、价值迭代 Value Iteration）来求解刚刚建立的经验模型。
  * 课件中给出的策略迭代状态价值更新公式（基于经验模型 $\hat{T}$ 和 $\hat{R}$）：
    $$V_{k+1}^{\pi_i}(s) \leftarrow \sum_{s'} \hat{T}(s, \pi_i(s), s') \left[ \hat{R}(s, \pi_i(s), s') + \gamma V_k^{\pi_i}(s') \right]$$

### 3.1.4 无模型的学习 (Model-Free Learning)
与基于模型的方法不同，无模型学习**完全不尝试去估计环境的转移概率 $T$ 和奖励函数 $R$**。

**核心思想**：直接从交互经验中学习价值函数（例如 Q 值）或策略（Policy），跳过构建环境模型这一步。
* 智能体只关心“在状态 $s$ 下采取动作 $a$ 到底好不好（价值多少）”，而不关心“采取动作 $a$ 后具体会以多少概率转移到哪个状态”。
* **常见算法**：Q-Learning, SARSA, 策略梯度 (Policy Gradient) 等。

### 3.1.5 对比：Model-Based vs. Model-Free

| 比较维度 | 基于模型 (Model-Based) | 无模型 (Model-Free) |
| :--- | :--- | :--- |
| **是否估计 $T$ 和 $R$** | 是，需要先建立环境的近似模型。 | 否，直接学习价值或策略。 |
| **样本效率 (Sample Efficiency)** | **高**。能充分利用收集到的少量数据进行反复规划和推演。 | **低**。通常需要与环境进行大量的交互才能收敛（需要海量数据）。 |
| **计算开销 (Computation)** | 训练时计算量大（需要在内部模型上做规划和迭代求解）。 | 训练时单步计算量通常较小，更新简单快捷。 |
| **误差与偏差 (Bias)** | 容易产生**模型偏差 (Model Bias)**。如果第一步学到的模型有误差，这个误差会在第二步的规划中被放大。 | 不受限于环境模型拟合的好坏，通常能学到更渐进无偏的最优解。 |
| **适用场景** | 状态/动作空间较小，或者环境规律容易被精确建模的场景（如棋盘游戏）。 | 状态/动作空间极其复杂，难以精确建模的真实世界场景（如自动驾驶、机器人控制）。 |

### 3.1.6 被动强化学习 (Passive Reinforcement Learning)
**核心概念**：智能体（Agent）的**策略是固定且已知**的。智能体不需要做任何决策，只需要像“顺风车乘客（along for the ride）”一样，严格按照给定的策略 $\pi(s)$ 在环境中执行动作，并通过与环境交互的经验来学习状态的价值。
* **简化任务**：策略评估 (Policy Evaluation)。
* **已知条件**：固定的策略 $\pi(s)$。
* **未知条件**：状态转移概率 $T(s,a,s')$ 和 奖励函数 $R(s,a,s')$。
* **最终目标**：学习并计算出在当前策略下每个状态的价值 (State Values)。
* **特点**：这不是离线规划（Offline planning），智能体必须在真实世界/环境中实际采取行动来收集数据。


### 3.1.7 主动强化学习 (Active Reinforcement Learning)

课件中只提到了被动强化学习（Passive RL），与之相对的核心概念是**主动强化学习 (Active RL)**。

#### 核心区别：是否拥有“决策权”
* **被动强化学习**：策略 $\pi$ 是**固定**的。智能体只负责执行和观察，目标仅仅是“评估”当前这个给定策略到底有多好（计算 $V^\pi$）。它不需要思考怎么做更好。
* **主动强化学习**：策略是**未知且需要学习**的。智能体不仅需要评估状态的价值，还需要**自己决定采取什么动作**，最终目标是找到一个**最优策略 $\pi^*$**（即能获得最大累积奖励的策略）。

#### 主动强化学习的特征与挑战：
1.  **从评估到优化**：智能体在学习状态价值（或 Q 价值）的同时，还需要不断更新和改进自己的策略。
2.  **探索与利用的困境 (Exploration vs. Exploitation Dilemma)**：
    * **探索 (Exploration)**：尝试未知的动作，以期发现潜在的更高奖励（即使短期内可能会遭受损失）。
    * **利用 (Exploitation)**：根据当前已知的信息，选择当前看起来最好的动作，以最大化眼前的奖励。
    * 在主动 RL 中，智能体必须在“利用已知好动作”和“探索未知动作”之间寻找完美的平衡，而被动 RL 完全不存在这个问题（因为动作是被强制规定好的）。

## 3.2 MC & TD

### 3.2.1 直接评估 (Direct Evaluation)
**核心思想**：通过经验采样，直接计算回报的平均值。
* **目标**：计算在策略 $\pi$ 下每个状态的价值。
* **具体步骤**：
    1. 按照既定策略 $\pi$ 在环境中行动（生成多个回合/轨迹）。
    2. 每当访问一个状态 $s$ 时，记录下从该状态开始直到回合结束所获得的**折扣奖励总和 (sum of discounted rewards)**。
    3. 将在状态 $s$ 收集到的所有样本结果求平均值，作为该状态的评估价值。

### 3.2.2 直接评估的优缺点分析
* **优点 (Positives)**：
    * 概念直观，容易理解。
    * 不需要环境模型（即完全不需要知道 $T$ 和 $R$）。
    * 只要样本足够多，最终一定能收敛到正确的状态价值。
* **缺点 (Negatives)**：
    * **忽略了状态之间的内在联系**：在马尔可夫决策过程（MDP）中，相邻状态的价值是强相关的，但直接评估将每个状态当作完全孤立的个体来分别学习。
    * **学习效率极低**：因为没有利用状态间的转移关系，收敛过程需要花费非常长的时间和海量的数据。

### 3.2.3 为什么不能直接使用传统的策略评估 (Policy Evaluation)？
在之前的 MDP 课程中，我们学过利用贝尔曼方程进行一步前瞻（one-step-look-ahead）的策略评估：
$$V_{k+1}^\pi(s) \leftarrow \sum_{s'} T(s, \pi(s), s')[R(s, \pi(s), s') + \gamma V_k^\pi(s')]$$
* **优势**：这种方法完美利用了状态之间的联系（当前状态的价值由其后继状态的价值推导而来）。
* **无法使用的原因**：由于强化学习的设定是环境未知，我们**没有 $T$（转移概率）和 $R$（奖励模型）**，因此根本无法计算上述期望方程。这也是为什么我们需要引入时序差分学习（TD Learning）等方法来结合直接评估和传统策略评估的优点（课件后续内容通常会引出这点）。

### 3.2.4 时序差分学习 (TD Learning) 
时序差分学习结合了动态规划（利用状态间联系）和蒙特卡洛（从经验中采样）的优点。

**核心思想 (Big Idea)**：
* **步步更新 (Learn from every experience)**：不需要等整个回合（episode）结束，每次经历一个状态转移 $(s, a, s', r)$ 后，就立即更新当前状态 $V(s)$ 的价值。
* **策略评估 (Policy Evaluation)**：此时策略依然是固定的，我们仍在做评估任务。
* **自举 (Bootstrapping)**：利用后继状态 $s'$ 的现有估计价值来更新当前状态 $s$ 的价值。

**更新公式**：
1. **计算单步样本 (Sample)**：这是我们在单步转移中观察到的“目标值”。
   $$sample = R(s, \pi(s), s') + \gamma V^\pi(s')$$
2. **结合历史价值更新 $V(s)$**：使用滑动平均（Running Average）的方式更新。
   $$V^\pi(s) \leftarrow (1 - \alpha)V^\pi(s) + \alpha(sample)$$
3. **公式的另一种等价形式**：更清晰地展示了“误差修正”的过程。
   $$V^\pi(s) \leftarrow V^\pi(s) + \alpha(sample - V^\pi(s))$$
   *(注：其中 $sample - V^\pi(s)$ 被称为 **TD 误差 (TD Error)**)*

**指数移动平均 (Exponential Moving Average)**：
* 引入学习率 $\alpha$ 进行插值更新，这本质上是一种指数移动平均。
* **注重近期经验**：这种更新方式会让系统更看重最近采样的结果，而逐渐“遗忘”久远过去的价值估计。这是合理的，因为在学习初期，我们对状态价值的估计往往是极其错误的。
* **收敛性**：随着学习时间的推移，逐渐减小学习率 $\alpha$（例如让 $\alpha$ 随时间衰减），可以保证价值函数的最终收敛。

### 3.2.5 时序差分 (TD) vs. 蒙特卡洛 (MC) 核心区别

TD 和 MC 都是无模型（Model-Free）的强化学习方法，但它们在“如何利用经验”和“何时更新”上有本质区别：

| 比较维度 | 时序差分学习 (TD Learning) | 蒙特卡洛方法 (Monte Carlo) |
| :--- | :--- | :--- |
| **更新时机** | **在线 (Online) / 步步更新**：每走一步 $(s, a, r, s')$ 就更新一次。 | **离线 (Offline) / 回合结束更新**：必须等一整个回合（Episode）完全结束后才能计算总回报并更新。 |
| **更新目标 (Target)** | **估计值 (Estimate)**：基于下一步的奖励 $R$ 和下一个状态的**估计价值** $V(s')$（这叫 Bootstrapping 自举）。 | **真实回报 (Actual Return)**：基于整个回合累积的真实折扣奖励总和。 |
| **方差 (Variance)** | **低**：因为只依赖单步的随机性（仅仅是下一步的状态转移和奖励）。 | **高**：因为依赖一整条长轨迹，整个回合中所有的随机动作和状态转移叠加在一起，导致每次得到的回报差异很大。 |
| **偏差 (Bias)** | **有偏差 (Biased)**：因为更新目标用到了 $V(s')$ 的当前估计值，而这个估计值一开始可能是不准的。 | **无偏差 (Unbiased)**：使用的是真实的累积回报作为目标，没有掺杂任何主观估计。 |
| **是否利用马尔可夫性** | **是**。隐式地利用了 MDP 状态之间的转移关系。 | **否**。完全忽略状态间的网络联系，把每个状态当成孤立的个体统计。 |
| **适用场景** | 适用于连续任务（Continuing Tasks）或回合很长、甚至可能无法终止的任务。 | 必须适用于分发任务（Episodic Tasks），即任务必须有明确的终止状态。 |

## 3.3 Q-Learning
### 3.3.1 从价值迭代到 Q-价值迭代 (Q-Value Iteration)
在已知环境模型（即知道状态转移概率 $T$ 和奖励 $R$）的情况下，我们可以使用动态规划来求解最优策略。
* **状态价值迭代 (Value Iteration)**：计算在状态 $s$ 下的期望最大累积奖励。
  $$V_{k+1}(s) \leftarrow \max_a \sum_{s'} T(s, a, s') \left[ R(s, a, s') + \gamma V_k(s') \right]$$
* **Q-价值迭代 (Q-Value Iteration)**：但在实际操作中，**Q 值 (Q-values)** 更加实用。Q 值表示在状态 $s$ 执行动作 $a$ 后的期望最大累积奖励。有了最优 Q 值，智能体不需要知道 $T$ 就能直接选出最优动作（直接取 $\max$ 即可）。
  $$Q_{k+1}(s, a) \leftarrow \sum_{s'} T(s, a, s') \left[ R(s, a, s') + \gamma \max_{a'} Q_k(s', a') \right]$$

### 3.3.2 Q-Learning：基于样本的 Q-价值迭代
在强化学习设定中，我们**不知道 $T$ 和 $R$**，因此无法直接计算上述期望。Q-Learning 的核心思想就是：**用从环境中采样得到的经验 (Samples) 来近似期望**。

* **算法流程**：智能体在环境中不断探索，每当经历一次状态转移 $(s, a, s', r)$，就更新一次 Q 值。
* **计算新样本估计 (Sample Estimate)**：结合当前获得的真实奖励 $r$ 和下一个状态 $s'$ 的最大估计 Q 值（即自举 Bootstrapping）。
  $$sample = R(s, a, s') + \gamma \max_{a'} Q(s', a')$$
* **滑动平均更新 (Running Average)**：利用学习率 $\alpha$ 将新样本的信息融合到旧的 Q 值估计中。
  $$Q(s, a) \leftarrow (1 - \alpha)Q(s, a) + \alpha [sample]$$
  *(这等价于：$Q(s,a) \leftarrow Q(s,a) + \alpha (sample - Q(s,a))$)*

### 3.3.3 Q-Learning 的性质与收敛条件 (Properties)
* **惊人的结果 (Amazing result)**：Q-Learning 能够收敛到**最优策略 (Optimal policy)**，即使智能体在收集数据时采取的是次优的、甚至是完全随机的动作。这种特性被称为**异轨策略学习 (Off-policy learning)**。
* **收敛的限制条件 (Limitations/Requirements)**：
  1. **充分探索 (Explore enough)**：必须保证所有的 $(s, a)$ 对都能被无限次地访问到。
  2. **学习率衰减 (Learning rate decay)**：学习率 $\alpha$ 必须逐渐减小，但不能减小得太快（满足随机逼近理论的 Robbins-Monro 条件）。
* **结论**：只要时间足够长且满足上述条件，你用来选择动作的策略（行为策略）具体是什么样并不重要，Q-Learning 最终都能学到最优的 Q 值。

### 3.3.4 异轨策略 (Off-policy) vs. 同轨策略 (On-policy)

这是强化学习中极其重要的一个区分点。要理解它们，首先要分清两个基本策略：
* **行为策略 (Behavior Policy)**：智能体用来在环境中游走、收集经验数据（也就是决定当前走哪一步）的策略。比如常见的 $\epsilon$-greedy 策略（有一定概率随机探索）。
* **目标策略 (Target Policy)**：智能体正在学习、优化并最终希望得到的策略。

#### 异轨策略 (Off-policy) —— 例如：Q-Learning
* **核心定义**：**行为策略 $\neq$ 目标策略**。你“用来学习的经验”和“你正在评估的策略”是不一样的。
* **在 Q-Learning 中的体现**：看 Q-Learning 的样本公式：$sample = r + \gamma \max_{a'} Q(s', a')$。
  * 在状态 $s'$ 时，公式里直接取了所有可能动作中的**最大 Q 值**（这意味着**目标策略是贪婪策略**，总是选最好的）。
  * 但是，智能体在真实环境中走到 $s'$ 后，**下一真实步**可能并没有选那个收益最大的动作，而是因为 $\epsilon$-greedy 随机选了一个差的动作（**行为策略包含探索**）。
  * 也就是说，Q-Learning “胆子很大”，无论实际怎么乱走，它在心里更新时总是假设“我下一步一定会做出最优选择”。

#### 同轨策略 (On-policy) —— 例如：SARSA
* **核心定义**：**行为策略 $=$ 目标策略**。智能体用来收集数据的策略，就是它正在评估和优化的策略。
* **在 SARSA 中的体现**：SARSA 的更新公式是：$sample = r + \gamma Q(s', a')$。
  * 注意这里**没有 $\max$ 操作**。公式里的 $a'$ 是智能体在状态 $s'$ 下**实际采取的动作**（由当前的 $\epsilon$-greedy 行为策略决定）。
  * 也就是说，SARSA “比较务实”，它在心里更新时会考虑：“既然我下一步有一定概率会犯错（探索），那我在评估当前状态价值时，必须把这个犯错的风险也算进去。”

**总结区别**：
Q-Learning (Off-policy) 学习的是一条绝对完美的路径，哪怕它在训练时跌跌撞撞；而 SARSA (On-policy) 学习的是一条考虑到自身偶尔会“手抖/犯错”的相对安全路径。

## 3.4 状态泛化与近似 Q-Learning (Approximate Q-Learning)

### 3.4.1 跨状态泛化 (Generalizing Across States)
**传统 Q-Learning 的局限性**：
* 基础的 Q-Learning（也叫表格型 Tabular Q-Learning）需要维护一张巨大的 Q 值表。
* 在现实世界中（如自动驾驶、复杂游戏），状态空间往往极其庞大。
* **无法遍历**：训练过程中不可能访问到每一个具体的状态。
* **内存爆炸**：计算机内存无法装下包含所有状态的超级表格。

**解决方案：泛化 (Generalization)**：
* 核心思想与机器学习的基础理念一致：通过在**少量训练样本**上积累经验，并将这些经验**泛化（推而广之）**到未曾见过的、但具有相似特征的新状态上。

### 3.4.2 基于特征的表示法 (Feature-Based Representations)
为了实现泛化，我们不再把状态当作毫无关联的孤立编号，而是提取它们内在的**特征 (Features)**。
* **特征的定义**：特征 $f_i(s)$ 是一个从状态映射到实数（通常是 0 或 1，或是具体数值）的函数，用于捕捉该状态下的关键属性。
* **吃豆人 (Pacman) 举例**：
  * 离最近幽灵的距离
  * 离最近豆子的距离
  * 当前画面中幽灵的总数量
  * 吃豆人是否在隧道中 (0 或 1)
* 同样地，我们也可以提取状态-动作对 $(s, a)$ 的特征，例如：“采取这个动作会让我离食物更近”。

### 3.4.3 线性价值函数 / 线性 Q 函数 (Linear Value / Q Functions)
有了特征之后，我们可以为每个特征分配一个**权重 (Weights, $w_i$)**。状态的价值或 Q 值可以直接表示为特征与其权重的线性组合（点积）：
$$V(s) = w_1 f_1(s) + w_2 f_2(s) + \dots + w_n f_n(s)$$
$$Q(s, a) = w_1 f_1(s, a) + w_2 f_2(s, a) + \dots + w_n f_n(s, a)$$

* **优势 (Advantage)**：极大地压缩了信息。我们将海量的试错经验浓缩成了几个具有强大表达能力的权重数字（只需学习几个 $w_i$，而不是几百万个状态的独立 Q 值）。
* **劣势 (Disadvantage)**：模型的表达能力受限于特征工程。如果特征设计得不好，可能会导致两个截然不同的状态具有相同的特征向量，算法将无法区分它们的真实价值。


### 3.3.4 近似 Q-Learning (Approximate Q-Learning)
在使用线性 Q 函数后，智能体的学习目标从“更新表格里具体的 Q 值”转变成了“**更新各个特征的权重 $w_i$**”。

* **第一步：计算时序差分误差 (TD Difference)**
  先算出现实与预期的偏差：
  $$difference = \left[ r + \gamma \max_{a'} Q(s', a') \right] - Q(s, a)$$

* **第二步：更新权重 (Weight Update)**
  区别于传统方法直接更新 $Q(s,a)$，这里我们通过梯度下降的思想来更新权重公式：
  $$w_i \leftarrow w_i + \alpha [difference] f_i(s, a)$$

**直观解释 (Intuitive Interpretation)**：
* 算法只调整那些在当前状态下**被激活 (active)** 的特征的权重（即 $f_i(s, a) \neq 0$ 的特征）。
* **“连坐/背锅”机制**：如果执行动作后发生了一件出乎意料的坏事（导致 $difference$ 为负），算法会“责怪”所有当时处于激活状态的特征，并降低它们的权重 $w_i$。
* **泛化效果**：由于权重降低了，未来**任何**包含这些特征的其他状态，其计算出的整体 Q 值也会随之降低，这就完美实现了“吃一堑，长一智”的跨状态经验泛化。
